# NOTES
# ---------------------------------------
# - Replace "evil.com" with your own controlled domain (Burp Collaborator,
#   interact.sh, or a domain you own) before fuzzing, so you get a
#   verifiable out-of-band hit instead of guessing from response codes.
# - Replace "trusted.com" with the actual target's own domain when using
#   Section 4/5 bypass payloads that rely on trusted-domain confusion
#   (e.g. user@evil.com, trusted.com.evil.com).
# - For /FUZZ usage: sections 3, 4, 6, 8 work as direct path replacement.
# - For param-based usage: sections 1, 2, 5, 7 work as full query strings
#   appended after the base URL, e.g. http://example.com/login?FUZZ
#   (strip the leading "?" if your target already has other params, and
#   use "&FUZZ" instead in that case).
# - Only use against systems you are explicitly authorized to test.
